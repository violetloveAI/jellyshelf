## 发布流程

1. 在仓库 **Settings → Pages** 中将 **Source** 设为 **GitHub Actions**。
2. 将已检查的代码推送到 `main`，或在 **Actions** 中手动运行 **Deploy JellyShelf to GitHub Pages**。
3. 等待工作流成功，再打开部署任务给出的地址完成下列检查。若工作流失败，先修复报错，不把预期地址作为已上线结果。

## 上线后检查

- `/jellyshelf/` 下的页面、样式、图标正常加载。
- 新浏览器的商品库为空，四款官方参考样例没有自动入库。
- 用专门的测试记录验证：新增、照片上传、刷新后查找、编辑、删除。
- 导出包含照片的 JSON，在另一浏览器预览并导入；再次导入会跳过已有记录。
- 拍照查货能从 `/jellyshelf/vision/` 加载模型与 WASM，并返回库内候选。
- iPhone Safari 的主屏幕入口可以打开网站；不把首次断网加载列为已支持能力。
- 所有测试记录仅保存在本地测试来源，正式公网首次打开为空资料库。不要把测试成交价格混入真实库存。

只有程序、构建所需静态资源和不含私人资料的截图进入公开仓库。JSON 商品备份、个人照片、密钥、浏览器储存内容和本机运行文件不应进入仓库。
